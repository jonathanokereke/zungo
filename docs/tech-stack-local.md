# Zungo — Local Development Tech Stack

This document describes every component that runs on your Mac during local development.

---

## Architecture overview

```
iPhone Simulator / Real Device
        │  HTTP (auto-detected IP or localhost)
        ▼
  Expo Dev Server (Metro)         ← hot-reload JS bundler
        │
  React Native App (Expo SDK 53)  ← mobile client
        │  HTTP :3001
        ▼
  Fastify API Server              ← business logic, Auth0 validation
        │  SQL
        ▼
  PostgreSQL (local)              ← user data, words, SRS cards
```

Auth0 (cloud) is always remote — there is no local Auth0 server.

### 3. API server — `server/api`

| Tool | Version | Role |
|---|---|---|
| **Fastify** | 4.x | HTTP server framework; fast, schema-based, plugin architecture |
| **tsx** | 4.x | Runs TypeScript source directly (no compile step in dev or prod) |
| **Drizzle ORM** | 0.33 | Type-safe SQL query builder; migration runner |

| **`postgres` (pg driver)** | 3.x | Low-level PostgreSQL connection pool |
| **@fastify/jwt** | 8.x | JWT verification plugin |
| **jwks-rsa** | 3.x | Fetches Auth0's public JWKS to verify RS256 tokens |

**Key files:**
- `src/index.ts` — starts Fastify, registers all route plugins, sets CORS

- `src/db/schema.ts` — Drizzle table definitions (single source of truth for DB shape)
- `src/db/migrations/` — SQL migration files generated by drizzle-kit
- `.env` — local secrets (gitignored); DATABASE_URL, Auth0, Anthropic key

### 4. Local database — PostgreSQL

| Property | Value |
|---|---|
| Engine | PostgreSQL 16 (Homebrew) |
| Host | `localhost:5432` |
| Database | `zungo_dev` |
| User | `zungo_user` |
| Connection string | `postgresql://zungo_user:devpassword123@localhost:5432/zungo_dev` |

**Key tables:**

| Table | Purpose |
|---|---|
| `users` | One row per Auth0 user; stores CEFR level, XP, preferences |
| `words` | German vocabulary linked to a user; CEFR level, part of speech, translations |
| `srs_cards` | One card per word; SM-2 fields: interval, ease, repetition, due_date |
| `grammar_sessions` | Completed grammar drills; topic, score, mastery % |
| `writing_sessions` | AI writing feedback sessions |
| `chat_sessions` / `chat_messages` | Conversation history with AI tutor |
| `reviews` | SRS review log; each card flip recorded |

### 5. Authentication — Auth0 (cloud, always remote)

| Property | Value |
|---|---|
| Tenant | `zungo.eu.auth0.com` |
| App type | Native (iOS/Android) |
| Token type | RS256 JWT |
| Audience | `https://api.zungo.app` |
| Custom claims namespace | `https://zungo.app` |

Auth0 is **not** run locally. The Simulator / device talks directly to Auth0's cloud servers for login. The API server calls Auth0's JWKS endpoint to verify tokens.

---

### 6. AI — Anthropic Claude (cloud, always remote)

| Property | Value |
|---|---|
| Model | `claude-haiku-4-5-20251001` |
| Uses | Grammar exercise generation, word lookup, AI tutor chat |
| SDK | `@anthropic-ai/sdk` on the API server |

All Claude calls go through the API server — the mobile app never calls Anthropic directly.

## Data flow: a typical API request

1. User taps a button in the app
2. `apiFetch()` in `api.ts` sends HTTP request to `http://<mac-ip>:3001/api/...`
3. Fastify receives the request; `verifyAuth` middleware validates the JWT against Auth0 JWKS
4. Route handler queries PostgreSQL via Drizzle ORM
5. (If AI needed) Route calls `anthropic.ts` → Claude API → parses response
6. JSON response sent back to the app
7. React state updates → UI re-renders
