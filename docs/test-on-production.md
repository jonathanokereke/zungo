# Testing the Mobile App Against Production Infrastructure

This guide shows how to run the Expo dev client on your iPhone/Simulator while pointing at the live Railway API instead of your local server.

---

## When to use this

- Validating a fix that is already deployed to Railway
- Testing Auth0 + production database together
- Checking that Railway is returning correct data before a release

---

## Step 1 — Confirm Railway is healthy

Open the Railway dashboard and verify the latest deployment is **Active**. Check the public URL is reachable:

```bash
curl https://<your-railway-url>.railway.app/health
# Expected: {"status":"ok"} or similar
```

---

## Step 2 — Create a production env file for the mobile app

**Do not edit `.env.local`** — that is your local dev config. Create a separate file:

```bash
# apps/mobile/.env.production  (already gitignored by *.env rule)
cat > apps/mobile/.env.production <<'EOF'
EXPO_PUBLIC_API_URL=https://<your-railway-url>.railway.app
EXPO_PUBLIC_AUTH0_DOMAIN=zungo.eu.auth0.com
EXPO_PUBLIC_AUTH0_CLIENT_ID=WiIK5cSrBucFQYeEs5gXDnNqcEgywta8
EXPO_PUBLIC_AUTH0_AUDIENCE=https://api.zungo.app
EOF
```

Replace `<your-railway-url>` with the actual URL from the Railway dashboard.

---

## Step 3 — Start Expo with the production env file

Expo reads `.env.local` by default. To use `.env.production`:

```bash
cd apps/mobile

# Copy production env over local for this session
cp .env.production .env.local

npx expo start --clear
```

> **Important:** Restore your local env when you're done testing:
> ```bash
> cp .env.local.backup .env.local   # if you saved a backup
> # or just set EXPO_PUBLIC_API_URL back to http://localhost:3001
> ```

A cleaner approach (no file swapping): pass the URL inline:

```bash
EXPO_PUBLIC_API_URL=https://<your-railway-url>.railway.app \
  npx expo start --clear
```

---

## Step 4 — Open the app

- **Simulator:** Press **i** in the Expo terminal
- **Real iPhone:** Scan the QR code with the Camera app (requires Expo Go installed, or a dev build)

---

## Step 5 — Log in

Use a real Auth0 account (not the dev mock). Auth0 will issue a JWT that Railway's API validates. All data written during this session goes to the **production database**.

---

## Step 6 — Run through the test checklist

| Feature | What to verify |
|---|---|
| Onboarding | Complete assessment → user row created in prod DB |
| Dashboard | XP, streak, recent activity load from Railway |
| Vocabulary | Words for your CEFR level appear |
| SRS Review | Cards load; rating saves to prod DB |
| Grammar | Topics for your level only; exercises generated by Claude |
| Reading | Texts load; word tap → translation works |
| Chat | AI tutor responds |

---

## Step 7 — Check the production database

Connect to Railway Postgres to verify data was saved:

```bash
psql "postgresql://postgres:<password>@<host>.railway.app:<port>/railway"
```

```sql
-- Confirm your user row exists
SELECT id, email, level, xp FROM users ORDER BY created_at DESC LIMIT 5;

-- Check SRS cards saved
SELECT COUNT(*) FROM srs_cards WHERE user_id = '<your-user-id>';
```

---

## Step 8 — Restore local env

```bash
# In apps/mobile/.env.local, set back to:
EXPO_PUBLIC_API_URL=http://localhost:3001
```

Or simply restart Expo without the override — the auto-detection kicks back in.

---

## Building a standalone production app (no Expo Go)

To test a fully native binary that behaves exactly like an App Store build:

```bash
# Requires EAS CLI: npm install -g eas-cli and an Expo account
cd apps/mobile
eas build --platform ios --profile preview
```

EAS will email you a link. Install via TestFlight or the EAS dashboard URL on your iPhone. This build always points to `EXPO_PUBLIC_API_URL` baked in at build time — set it to your Railway URL in `eas.json` under the `preview` profile.
